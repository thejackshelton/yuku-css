# Decisions

- The AST is css-tree 3.2.1's, and css-tree's own fixtures are the parity suite (`bun run sync`).
- Where css-tree accepts what the CSS specs reject, yuku-css follows the specs; every such case is listed in `test/divergences.ts`.
- The lexer validates against `@webref/css` (W3C spec extracts), not mdn-data; where the two disagree with css-tree's fixtures, the case is listed as a divergence.
- The benchmark compares against css-tree, PostCSS, and Lightning CSS (native and wasm), always on equal work.
- The tree is css-tree's; parse errors the current CSS Syntax 3 draft defines (unclosed comment, string or url, bad escapes, newline in a string) are reported even where css-tree is silent, end of input inside a block is not (the current draft dropped it), and Selectors 4 syntax css-tree lacks (`||`) is parsed; all listed as divergences.
- `yuku-css/codegen` and `yuku-css/ast` are TypeScript over the decoded tree, as Yuku's are, and keep css-tree's function names. They take any css-tree tree, with arrays or `List`s, and `generate` matches css-tree's output and source maps byte for byte, so they are tested on trees css-tree parses.
- `yuku-css/lexer` is css-tree's lexer with its matching algorithm ported to Zig node for node, so over the same grammar it answers as css-tree does; the grammar is compiled from `@webref/css` at build time and embedded in a WebAssembly module of its own, so the parser does not carry it.
- At-rule preludes are parsed by default, into css-tree's prelude nodes, with `@custom-media`'s read per Media Queries 5 into an `Identifier` and a `MediaQueryList` or `Identifier`, as `@container`'s name sits beside its condition; parentheses in a condition read as a nested condition or as general-enclosed, and a function no condition knows, report none of the errors of the terms css-tree tries there first, since the grammars accept them all; parentheses whose condition those grammars reject are general-enclosed, as the grammars read them; where the condition grammars of Media Queries 4, CSS Conditional 3 and CSS Contain 3 reject what css-tree reads outside parentheses, the tree stays css-tree's with a diagnostic, and the end of input closes an open feature, range, condition, `@scope` selector or `@import` function, as it closes every block; all listed as divergences.
- The lexer's results keep css-tree's shapes, but its errors carry no stack frames, a declaration written as an earlier one in the same `matchStylesheet` call shares that one's match tree, and a whole sheet matches in one call into the WebAssembly; the speed of validating a sheet is judged against css-tree parsing it and matching each declaration, with every result read.
- `transform` is on the main entry beside `parse` and `tokenize`, since it is one call into the same WebAssembly instance; it prints with a Zig printer over the Zig tree that matches `yuku-css/codegen`'s `generate` byte for byte, source maps included, and returns no tree. Its output is css-tree's compact text; restructuring minification, as csso or Lightning CSS's `minify` do, is out of its scope.
- `parse` decodes diagnostics, comments and tokens at once and builds the tree when `ast` is first read, as Yuku builds `program`; the tree is read straight from wasm memory, and copied out only when another call comes first.
- The inlined WebAssembly is printable ASCII, each byte one character or two by how often it occurs, which gzip compresses as well as the `.wasm`; base64 compresses 40% worse.
